## 후속 결정 — 공통 계약은 양쪽 모두 수정 가능

- 결정: 사용자 요청으로 Windows 필수 통합 단계를 없앤다. Pi·Jetson 모두 `shared/`, 공통 `docs/`,
  `dashboard/src/data/schema.js`, 중앙 개발·결정 노트를 수정할 수 있다. 런처 지침과 경로 검사도 함께 수정했다.
- 이유: API를 필요로 하는 쪽에서 계약과 자기 구현을 함께 개발하고 상대 장비에 인계할 수 있어야 한다.
- 대안: Windows 전담은 불필요한 병목이며, 모든 장비 코드를 무제한 개방하면 담당 분리 목적이 흐려진다.
  따라서 상대 장비 전용 코드·문서·노트와 나머지 도구·설정은 기존 경계를 유지한다.
- 공통 변경 하나당 담당 브랜치를 정하고 예시·호환성·상대 수정·검증·적용 순서를 역할 노트에 남긴다.
  중앙 노트는 병합 담당이 요약하며 D 번호는 병합 시 정한다. 기존 미푸시 D-036은 선점하지 않는다.
- 검증: 양쪽 역할에서 공통 파일의 비추적/스테이징/커밋 상태를 허용하고, 상대 문서·노트와 설정 변경은
  차단하는 회귀 검증을 추가했다. 장비 설치·실제 Claude 실행은 이번에도 수행하지 않았다.

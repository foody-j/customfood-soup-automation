# 의사결정 기록 (Decision Log)

> 기술 선택·설계 결정을 남긴다. 형식: **결정 / 이유 / 대안 / 날짜**

## D-001 · 대시보드 우선 개발
- **결정:** 하드웨어/AI 전에 대시보드 프론트엔드를 먼저 만든다(목 데이터 구동).
- **이유:** "무엇을 보여줄지"를 정하면 Jetson이 무엇을 추론·전송해야 하는지 스펙이 역으로 확정됨. 하드웨어 없이도 진도가 나가고 데모가 빠름.
- **대안:** AI 추론부터 개발 — 그러나 출력 스펙이 안 잡혀 대시보드와 계속 어긋날 위험.
- **날짜:** 2026-07-10

## D-002 · 대시보드 스택 = React + Vite
- **결정:** React + Vite로 웹 대시보드 구축.
- **이유:** 실시간 차트/UI 유연, 확장성 좋음, Pi에서 브라우저(키오스크)로 구동 가능.
- **대안:** Streamlit/Dash(빠르지만 커스터마이징 제한), Next.js(Pi에 과함).
- **날짜:** 2026-07-10

## D-003 · 통신 방식 = MQTT
- **결정:** Jetson ↔ Pi 통신은 MQTT. Pi에 Mosquitto 브로커, 브라우저는 MQTT-over-WebSocket으로 직접 구독.
- **이유:** 실시간 텔레메트리에 표준적으로 최적. pub-sub이라 로거/알람/액추에이터 추가가 쉬움(느슨한 결합). 별도 백엔드 서버 불필요.
- **대안:** WebSocket 직결(양방향 간단하나 다중 구독/확장 약함), REST 폴링(단순하나 실시간성 낮음).
- **날짜:** 2026-07-10

## D-004 · 개발 도구 = micromamba 사용자 영역 설치
- **결정:** 시스템 apt(sudo) 대신 micromamba env로 Node 20 + git을 사용자 영역에 설치.
- **이유:** 이 머신에서 sudo 비밀번호 없이 설치 필요. 재현성 있고 시스템 오염 없음.
- **대안:** apt/NodeSource(sudo 필요), nvm(node만).
- **날짜:** 2026-07-10

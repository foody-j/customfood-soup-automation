## 1. 프로젝트 목적과 범위

알루미늄 프로파일 프레임에 여러 카메라와 조명을 여유 있게 장착하여, 조리 과정의 영상·깊이·열화상·적외선 데이터를 수집하고 다양한 실험을 할 수 있는 장치를 만든다.

- 센서별 활용 목적이나 AI 모델을 지금 고정하지 않는다. 먼저 장착·개별 제어·촬영·저장·확장이 가능한 기반을 만든다.
- 배식, 배식용 그릇 위치 보정, 배식량 측정은 범위 밖이다.
- 기존 문서의 국·탕 조리 맥락은 유지하되, 자동 조리 제어·익힘 판정·로봇 동작을 이번 구현의 필수 목표로 추가하지 않는다.
- 모든 센서를 장착한다는 요구와 모든 센서를 최고 설정으로 동시에 처리한다는 요구는 구분한다. 후자는 미확정이며 실제 부하를 측정해야 한다.

## 2. 확정한 장치 구성과 역할

| 구성 | 역할 / 결정 사항 |
|---|---|
| Jetson Orin Nano | 카메라 연결·영상/깊이 수집·원본 저장·필요한 AI 처리. Orin NX로 바꾸어 해석하지 않는다. |
| Raspberry Pi | 부하를 낮게 유지하며 상시 켜두는 장비 관리 PC. 관리 화면·명령·상태 감시 담당. 필요 시 Jetson ON/OFF·복구 기능 추가. |
| 모니터 | 라즈베리파이에 연결하는 방향. |
| Orbbec Gemini 2 | 사용자가 지정한 3D 카메라. USB 연결. |
| GMSL2 카메라 | 프레임에 장착. 모델·수량·캡처 보드는 미확정. |
| 열화상 카메라 | 프레임에 장착. 모델·인터페이스 미확정. |
| 적외선 장치 | 별도 장착 방향. 카메라/조명 구분과 파장 등은 미확정. 현재 설계의 NIR 해석은 가정. |
| 순간 플래시 | 촬영 시 순간 발광 기능 포함. 광원 종류·출력·펄스 폭·주기는 미확정. |
| 기존 노트북·AI PC | 개발·분석·학습·원격 접속용. 장비에 노트북을 상시 추가 설치하는 것을 필수로 잡지 않는다. |

라즈베리파이를 쓰는 이유는 가벼운 관리 업무를 맡겨 계속 응답하는 관리 경로를 확보하기 위해서다. 남는 성능을 소진하려고 무거운 영상 처리나 AI를 추가하지 않는다. 관리·연산 분리라는 설계 의도를 보존한다.

## 3. 시스템 구조

```text
Gemini 2 ─ USB ───────────────────┐
GMSL2 카메라 ─ 대응 캡처 보드 ────┤
열화상/적외선 ─ 지원 인터페이스 ───┘   Jetson으로 수집

                                   Jetson Orin Nano ─ 로컬 저장장치
                                            │
                                         유선 LAN
                                            │
                                      Raspberry Pi ─ 모니터
                                       │
                                       ├─ 관리 서비스·화면·설정·로그
                                       └─ Jetson 전원 제어 인터페이스 (추후 구현)

촬영 요청 ─ 하드웨어 타이밍 제어기 ─ 카메라 트리거 / 플래시 드라이버
```

카메라는 우선 Jetson 연결을 검토한다. 특정 센서의 ARM SDK 미지원이나 대역폭 문제로 호스트 분리가 필요하면 근거를 기록하고 변경한다. 위 그림의 라즈베리파이는 카메라 원시 데이터의 기본 경유지가 아니다.

- 관리 화면과 백엔드는 Pi에서 실행한다. Jetson이 꺼져도 상태 조회와 전원 조작 화면은 동작해야 한다.
- Jetson은 수집 서비스와 API를 제공한다. Pi는 제어 명령·상태·낮은 해상도/FPS의 미리보기를 주고받는다.
- 원본 데이터는 Jetson 로컬에 저장한다. 호환 NVMe SSD를 후보로 검토하되 용량·구매 여부는 미확정이다.
- Pi가 관리하는 실험 메타데이터와 Jetson이 저장하는 원본은 공통 session_id로 연결한다.
- 순간 플래시의 정밀한 노출 동기화는 하드웨어 타이머/트리거 장치가 담당한다. 웹 요청이나 Pi의 일반 OS 타이밍을 정밀 발광 기준으로 쓰지 않는다.

## 4. 소프트웨어 구현 제안

아래는 논리적 역할 구분이다. 저장소에 이미 프레임워크·서비스·API 규칙이 있으면 그 구조를 우선 활용한다.

### Pi 관리 서비스

- 대시보드: Jetson 연결·부팅 상태, 카메라 연결, 저장 상태, 촬영 시작/종료, 설정, 미리보기.
- 실험 설정: 활성 센서, 지원되는 해상도/FPS, 노출·조명 설정, 실험 이름·메모.
- 장비 감시: Jetson 응답과 촬영 서비스 상태를 구분해 감시. 오래된 상태/미리보기는 갱신 중단 표시.
- 필요 시 전원 제어와 복구 이력, 원격 접속, 저속 센서 기록 추가.
- 브라우저가 종료되어도 관리 서비스는 계속 실행.

### Jetson 수집 서비스

- 카메라별 어댑터로 연결/해제, 지원 기능 조회, 스트림 시작/종료, 설정, 상태를 관리.
- Gemini 2부터 실제 수집 경로를 검증. 다른 센서는 모델 확보 전 모의 장치로 UI/API를 개발할 수 있으나 실제 연동 완료로 표시하지 않는다.
- 원본 저장과 미리보기 생성을 구분하고, 저장 누락·장치 분리·디스크 부족을 기록.
- 촬영 상태와 종료 처리: 중복 시작 방지, 종료 요청 재시도 처리, 저장 완료 후 세션 닫기.
- 통신이 끊겨도 진행 중 로컬 수집 상태를 보존하고, 재접속 시 Pi와 상태를 다시 맞춘다. 통신 단절만으로 즉시 전원을 끄지 않는다.
- AI 기능은 수집 기반 검증 후 선택적으로 추가.

### 공통 데이터

- session_id, sensor_id, frame_id, 장치 시각, 호스트 수신 시각.
- 실제 노출 시각은 장치가 제공할 때 저장. 수신 시각을 노출 시각으로 대체해 표기하지 않는다.
- 해상도/FPS/픽셀 형식/노출/게인, 조명 모드, 플래시 명령, 센서·SDK·펌웨어 버전.
- 깊이와 온도 원본, 유효성·누락·오류, 보정 버전. 온도 원시 데이터 확보는 열화상 모델 선정 조건으로 제안한다.
- 여러 장치의 시계 오프셋·드리프트와 프레임 간 시간 차이를 기록. 시각을 맞춰 저장한 것만으로 하드웨어 동기화 완료라 하지 않는다.

## 5. Jetson 전원·복구 기능의 조건

- Pi 전원은 Jetson을 꺼도 유지되는 별도 분기로 구성.
- Jetson을 켜는 물리적 경로는 캐리어 보드에 맞는 전원 버튼 인터페이스 또는 규격에 맞는 전원 스위치로 설계. 정확한 보드 확인 전 핀 번호·전압·부품을 확정하지 않는다.
- 정상 종료: 새 촬영 차단 → 수집 중지·저장 완료 → OS 종료 → 적절한 상태 피드백으로 종료 확인 → 필요 시 전원 차단.
- 복구: 서비스 재시작 → 가능한 경우 OS 재부팅 → 지속 무응답 시 최후 수단으로 전원 재인가. 재시도 제한·대기 시간·이력 기록 포함.
- 부팅·촬영·정상 종료 중 상태를 구분하고, ping 실패 하나로 전원 차단하지 않는다.
- 하드웨어가 없을 때 전원 버튼은 미지원으로 표시하거나 명시적인 모의 모드로만 제공. 실제 전원을 제어하는 것처럼 보이게 만들지 않는다.

## 6. 기구·카메라 통합 시 확인

- 프로파일에 상부·측면 장착 위치와 추가 센서 공간을 확보. 카메라 높이·각도·조사 각도를 각각 조절.
- 공통 촬영 영역, 케이블 고정·여유 길이, 열·증기·튀김/국물 튐에 대한 보호 구조 검토.
- Gemini 2 내장 IR과 별도 적외선 조명, 플래시의 간섭을 실측. 동시/순차 촬영 모드를 비교하고 최종 타이밍 확정.
- Gemini 2의 내장 RGB는 롤링 셔터다. 순간 플래시용 GMSL2 카메라는 글로벌 셔터·외부 트리거·노출 신호 지원을 우선 검토하되 모델 선정 전 보장하지 않는다.
- 열화상 보호창은 사용 파장 대역에 맞춰 선정. RGB용 투명창을 모든 센서에 일괄 적용하지 않는다.
- 기존 PT100·PLC·가열부 구상은 참고 사항이며 이번 인계만으로 보유·구현 확정 장비로 취급하지 않는다.

## 7. 진행 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 기존 Git 저장소·지침·구현 구조와 실제 장비 목록 확인 | 기존 기능/신규 작업/미확정 항목을 구분한 구현 계획 |
| 2 | Pi 관리 서비스 ↔ Jetson 수집 서비스 기본 통신 | Jetson OFF/미연결 상태에서도 관리 화면 사용, 상태 조회·명령 왕복 |
| 3 | Gemini 2 수집·저장·미리보기 | 실제 데이터 저장 및 재열기, 설정·시각·장치 정보 기록 |
| 4 | GMSL2·열화상·적외선 순차 추가 | 지원 모델별 단독 수집과 장치 분리/재접속 처리 검증 |
| 5 | 플래시·트리거·센서 간섭 검증 | 실제 노출과 발광 타이밍 측정, 가능한 촬영 모드 명시 |
| 6 | 필요 시 Jetson 전원 관리 추가 | 정상 종료·켜기·제한된 장애 복구를 실제 회로로 검증 |
| 7 | 원하는 조합으로 연속 수집 | 실제 FPS·누락·CPU/GPU/RAM·온도·기록 속도를 보고. 초기 30분 후 실제 실험 길이로 확대 |
| 8 | 데이터 기반 연구 기능 추가 | 사용자가 선택한 과제에 맞춰 AI·센서 융합 기능 평가 |

하드웨어가 없는 개발 머신에서는 모의 장치로 상태 전이·UI·API·세션 관리를 진행하고, 실물 연결·촬영·전원 시험 결과와 분리해서 보고한다.

## 8. 미확정 입력

- Orin Nano 4GB/8GB, 캐리어 보드 모델/리비전, JetPack 버전.
- Pi 모델·메모리·OS·전원, 모니터 사양.
- GMSL2 카메라와 디시리얼라이저/캡처 보드, 열화상·적외선 모델과 SDK.
- 촬영 대상 영역·설치 높이·거리, 센서 수량, 원하는 동시 촬영 조합·FPS·실험 시간.
- 플래시 종류·파장·출력·반복률. 현재 가시광 LED 스트로브라는 해석은 가정이다.
- 전원 제어 회로·종료 상태 피드백과 예산.

미확정 사양을 임의로 구매 확정이나 동작 검증 완료로 바꾸지 않는다. 독립적으로 가능한 소프트웨어 작업은 진행하되 보드별 드라이버·전원 배선은 해당 입력 확보 후 확정한다.

## B. 기존 자산 — 플랜 §4 "저장소 구조 우선 활용"에 해당

- **React+Vite 대시보드** (`dashboard/`) — 플랜의 "Pi 관리 화면" 기반으로 확장 가능.
  데이터 소스 추상화(`useCookingData.js` mock↔mqtt 교체 구조)가 플랜의 "모의 장치 우선
  개발" 요구와 정확히 같은 패턴.
- **MQTT 계약 3문서** (`docs/data-schema.md` / `shared/schema.json` / `dashboard/src/data/schema.js`)
  — 상태·미리보기 채널로 재활용 가능. 단 session/sensor/frame 메타데이터는 신규 정의 필요(§C).
- **Jetson 툴체인·벤치** (`JETSON_SETUP.md`, `jetson/bench/`) — 플랜 7단계(연속 수집 부하 실측)의
  전력·온도 측정 코드(tegrastats 샘플러) 재사용 가능.
- **Pi 셋업 문서** (`PI5_SETUP.md`) — Mosquitto+대시보드 서빙 기준. 관리 서비스 추가 시 갱신.
- **NVENC 부재** (플랜 §9) — Orin Nano 확정이므로 해당됨. 영상 저장은 HW 인코딩 불가 →
  raw/MJPEG 저장 또는 CPU 인코딩, 7단계 부하 실측에 반드시 포함할 것.

## C. 신규 작업 (저장소에 전혀 없음)

1. **Orbbec Gemini 2** (USB 3D) — SDK v2 설치·수집 경로 전체가 신규. 플랜 3단계.
2. **Jetson 수집 서비스** (카메라 어댑터·세션 관리·저장·미리보기 API) — 기존엔 "MQTT 발행자
   스켈레톤" 구상만 있었음. 플랜의 서비스 설계가 이를 대체·확장.
3. **Pi 관리 서비스** (백엔드 + Jetson 전원/복구 제어) — 기존 대시보드는 뷰어일 뿐 관리
   백엔드 없음.
4. **session_id 중심 공통 데이터 스키마** — 기존 `cooking/status`는 실시간 상태용.
   수집 세션 메타데이터(노출 시각·버전·오프셋 등) 스키마는 신규.
5. **플래시·하드웨어 타이밍 제어기, 적외선 장치** — 전부 신규(모델 미정).
6. **알루미늄 프로파일 프레임** 장착 설계 — 기존 문서의 "솥 위 지그" 구상을 대체.

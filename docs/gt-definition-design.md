# GT(조리 완료 정답) 정의 · 데이터 수집 프로토콜 설계안

> 2026-07-12 초안. 문제: "조리 완료" GT가 미정 → 학습·평가의 정답을 어떻게 만들지 확정한다.
> 근거: 튀김 도미 doneness 논문(ScienceDirect 2025)의 **방법론만** 이식. 상세는 `research-methodology.md` [S2].
> **결정됨**: 완료를 **3단계(미완 / 완료 / 과조리)** 다중분류로 정의.

> ⚠️ **도미 논문과 국/탕의 차이 (중요)**: 도미는 튀김이라 **겉면 갈변(색)이 익음의 주신호**(색-doneness 상관 0.93). 국/탕은 표면 색 변화가 약함 → **색·표면 비전(접근 B) 단독은 국/탕엔 약할 수 있음.** 도미 논문에서 가져오는 것은 구체 피처(색)가 아니라 **"여러 신호를 클러스터링해 완료 단계를 정하는 GT 생성 절차"**뿐. 국/탕에선 무게중심이 **중심온도+시간(A) + 건더기 무름/국물 우러남**으로 이동할 가능성이 크므로, **A+B 융합** 또는 **건더기 상태 인식**을 우선 검토한다.

---

## 1. 3단계 조작적 정의 (operational definition)

| 단계 | 라벨 | 의미 | 자동화 관점 |
|---|---|---|---|
| 0 | `undercooked` (미완) | 아직 더 끓여야 함 | 대시보드: "대기" |
| 1 | `done` (완료) | 지금이 최적 배식 시점 | **대시보드: "완료 알림" ← 시스템의 목표 출력** |
| 2 | `overcooked` (과조리) | 너무 졸았음/퍼짐, 품질 저하 | 대시보드: "경고" |

- 핵심 출력은 **0→1 전이 시점(=완료 알림)**. 2단계(과조리)는 완료를 놓쳤을 때의 안전망 + 학습 시 경계 명확화용.
- 국/탕은 "정답 시점"이 폭(band)을 가짐(예: 완료 후 5분간 여전히 완료). → 완료를 **점이 아닌 구간**으로 라벨.

## 2. GT 신호 — 제안 (하이브리드, 도미 논문 방식)

단일 신호로는 부족하다. **세 신호를 역할 분담**하는 하이브리드가 결론이다.

| 신호 | 장점 | 단점 | 이 설계에서의 역할 |
|---|---|---|---|
| **중심온도(MLX90614)+시간** | 자동·대량, 사람 손 거의 0, 재현성 높음 | 온도만으론 "맛/식감 완료"와 불일치 가능 | **1차 약지도(weak label)** — 모든 세션에 자동 부착 |
| **관능평가(사람)** | 진짜 정답에 가장 근접(도미 논문 기준) | 느림·주관적·비용 큼 | **의미 앵커** — 소량 세션에서만, 클러스터 경계 검증·명명 |
| **색(CIELAB, 카메라)** | 자동, doneness와 상관 0.93[S2] | 조명·거품·김서림에 민감 | **보조 피처** — 클러스터링 입력 + 시각모델 타당성 확인 |

### 권장 GT 생성 파이프라인 (도미 논문 replicate)
```
각 조리 세션 동안 동기 로깅: 시간 t, 중심온도(90614), 표면온도맵(90640),
                              RGB 2뷰, 색지표(CIELAB a*/b*)
        │
        ├─ (소량 세션) 사람 관능평가로 "완료 구간" 태깅  ← 앵커
        │
        ▼
  다변량 클러스터 분석(온도·색·시간·[관능])  →  3개 군집 = 미완/완료/과조리
        │
        ▼
  군집 경계를 시간축 임계값으로 환산  →  전 세션에 3단계 라벨 자동 전파
```
- 즉 **접근 A(온도·시간)가 접근 B(시각)의 라벨러**가 된다 — 조사에서 도출한 상보 전략.
- 관능평가는 **전 세션이 아니라 메뉴당 소수(예: 20~30세션)만** → 비용 절감하면서 정답 앵커 확보.

> ❓ **지도교수 확인 필요**: 관능평가를 몇 명/어떤 기준(맛·식감·외관)으로 할지, "완료"의 학과 정의가 있는지.

## 3. 데이터 수집 프로토콜

### 3.1 센서 · 동기화
- RGB 탑뷰, RGB oblique, MLX90640(32×24 thermal), MLX90614(중심온도) → **공통 타임스탬프**로 동기 저장.
- 프레임 레이트: RGB 1~2 fps로 충분(조리는 느린 과정). 온도는 1 Hz.
- **정합(calibration)**: RGB↔thermal은 **가열 체커보드 스테레오 캘리브**[S14] 1회 수행 → 정합 파라미터 저장.

### 3.2 세션 설계 (메뉴별)
- **핵심: 완료 시점을 넘겨서 과조리까지** 계속 촬영해야 3단계가 다 잡힘. (조리 시작 ~ 과조리까지 1세션.)
- 변량을 일부러 넣기: 불세기, 물양, 재료량, 초기온도, 뚜껑 유무 → 일반화·강건성.
- 반복: 메뉴당 최소 수십 세션 목표(정확 수치는 PoC 후 학습곡선 보고 결정).

### 3.3 메뉴 범위 (여러 종 → 단계적)
1. **PoC 1종 먼저** — 완료 신호가 뚜렷한 국/탕 1개로 파이프라인 검증. (후보 논의 필요: 미역국/된장국/김치찌개 등.)
2. 검증되면 2~3종 추가 → 공통 3단계 스키마로 일반화 테스트.

> ❓ **결정 필요**: PoC로 시작할 메뉴 1종.

## 4. 라벨링 · 어노테이션 실무
- **약지도 자동라벨**(온도·시간 임계값) → CVAT로 불러와 **시간구간 라벨 검수/보정**[S19].
- CVAT 선택 이유: 시간구간(start/end) 라벨 + RGB+thermal 멀티모달 + SAM2 보간(수작업 −90%)[S20].
- 산출물: 세션별 `(t, 단계라벨, 온도, 색, 뷰별 프레임경로)` 테이블 → 학습셋.

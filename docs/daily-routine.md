# 하루 루틴 — 조리 데이터 수집 (2026-10-05)

데이터셋 세션을 할 때마다 이 순서를 따른다. 자세한 조리 절차는 `docs/cooking-protocol.md`, 데이터 도구는 `research/README.md`.
명령은 Fedora 저장소 폴더에서 `research/soup <명령>`으로 친다.

## 실험 전 (5분)
1. **카메라 렌즈 닦기, 초점 확인** — Pi 화면 미리보기가 선명한지 본다. 지난 요약 이미지에 "⚠ 흐림"이나 "⚠ 김"이 있었다면 반드시.
2. **PT100 탐침** — 국 가운데, 늘 같은 깊이로 고정한다(깊이 mm는 조건 칸에 적는다).
3. Pi **'점검 60초' 프리셋** → 시작 전 점검이 모두 정상인지 본다.
4. Pi **'데이터셋' 프리셋** → 조건 칸을 채운다: 출력, 추가 물(mL), 뚜껑, 시작 온도, 탐침 깊이, 제품 실측 무게(g), 판정자.
   - 제품 무게를 적어야 열량·증발량을 추정할 수 있다.

## 실험 중
- 프로토콜 4절대로: 재료 투입 → 가열 → 끓음 → 맛보기(끓은 뒤 2분마다, 완료 근처 1분) → 완료 시작/끝 → **과조리까지 계속** → 가열 종료.
- 버튼을 놓쳤으면 **바로 사후 입력**(발생 시각 지정)한다. 다음 날 입력해도 Fedora가 최근 7일 기록을 밤마다 다시 받는다.

## 실험 후
- 중지할 때 뜨는 경고(정답 사건 누락)를 확인한다. 그 밖에 할 일은 없다 — **밤 1시에 Fedora가 자동으로 가져간다**
  (반출 → 무결성 검사 → Pi 기록 → QC → 요약 이미지 → 카탈로그).

## 다음 날 아침 (5분)
1. `research/soup status` → 마지막 줄이 **"정상"** 인지.
2. `~/soup-data/summary/<세션>.png` 를 본다. ⚠ 표시: 카메라 흐림·김 서림, 끓는 구간 온도 이상(탐침), 사건·조건 누락.
   자세한 숫자는 `~/soup-data/qc/<세션>.md` 맨 위 "자동 경고".
3. 판정을 남긴다.
   - 문제없음: `research/soup review <세션> use`
   - 애매함: `research/soup review <세션> hold --reason "이유"`
   - 못 씀: `research/soup review <세션> drop --reason "이유"`
4. 놓친 사건이나 조건이 있으면 Pi에서 사후 입력한다 → 그날 밤 자동 반영.

## 금요일
- `~/soup-data/weekly/weekly-<날짜>.md` (금요일 밤 자동 생성)를 본다: 조건별 세션 수(빈 조합), 판정 현황, 경고 많은 세션, Jetson 여유.
- 다음 주 조건 순서와 프로토콜 조정을 정한다. 기록은 `notes/fedora/weekly-<날짜>.md` (Claude에게 맡겨도 된다).

## 막힐 때
- 야간 작업 로그: `~/soup-data/logs/nightly-<날짜>.log`, `journalctl --user -u soup-nightly`
- Fedora의 Claude에게 "status랑 오늘 야간 로그 보고 문제 찾아줘"라고 하면 된다.
